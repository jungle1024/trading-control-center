# Global Trading Control Center

미국 주식 3대 전략(폴 튜더 존스 · 로스 카메론 · 올리버 켈) **통합 운영 대시보드**.
세 웹앱은 독립적으로 분석·매매하고, 이 앱은 결과만 읽어 **시장 상태 · 앱 가동 상태 · 실제 손익 · 위험 · 조치 필요 사항**을 한 화면에 보여 준다.

## 설계 원칙 (구축 가이드 V1.0)
- 기존 3개 웹앱 **코드·DB 변경 없음**. 주문 권한·증권사 주문 키 없음. 이 서버가 멈춰도 자동매매는 영향 없음.
- 데이터: 각 앱 공개 `/health` + 공유 DB `ptj_/rc_/kc_` 테이블 **읽기 전용 트랜잭션**. 대시보드 기록은 `dash_` 테이블만 사용.
- 정상 판정 4단계: 서버 → 데이터 → 분석 → 거래. 휴장·장 마감 후 '신호 없음'은 장애가 아님(NYSE 달력 기준).
- 신호 · 주문 요청 · 실제 체결 · 실현손익을 구분. 실현손익과 평가손익은 합산하지 않음.
- Kell: '오늘 매매 없음'(조건 미충족, 정상)과 '오늘 분석 안 함'(야간 스캔 실패/지연, 장애)을 구분.

## 화면
| 메뉴 | 내용 |
|---|---|
| Overview | 3가지 질문(시장 안전? 시스템 정상? 조치 필요?) · 조치 목록 · 시장 · 앱 상태 · 성과 · 위험 · 이벤트 |
| Market · Jones | 시장 단계·전일 대비 변화·지수 이동평균 관계·참여도·섹터·종목 발굴·경보 KPI |
| Strategies | Ross·Kell 동일 기준 성과 비교, 실행 흐름(스캔→신호→주문→체결→청산), Jones 분석 KPI |
| Portfolio & Risk | 계좌별 현황, 보유 포지션·손절까지 위험, 손실한도 사용률, 중복 보유 |
| Events & Health | 4단계 판정표, 작업 기록, 통합 이벤트(영구 저장·중복 제거), 해제된 문제 |
| Reports | 장 마감 후 일일 보고서(잠정→확정), ntfy 발송 |

## 알림 (ntfy)
- P1 긴급(주문 상태 불명·손실한도 초과·엔진 장애·미가동) / P2 중요 — **최초 발생·악화·해제** 시점만 발송.
- 발송 성공 ≠ 확인. 화면의 [확인] 버튼이 관리자 확인 기록(`dash_issues`). 발송 실패는 다음 주기 재전송.
- 일일 보고서: 마감+3시간 이후 조건 확인 → 잠정 발송 → 조건 충족 시 확정 재발송.
